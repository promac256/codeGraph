codeGraph

A knowledge-graph engine for LLM coding assistants. It indexes a git repository into a queryable symbol graph, serves it to agents over MCP, and compresses it into session-start context packs — so assistants navigate code by structure instead of reading files.

18MCP query tools
6languages, tree-sitter parsed
2–8ktokens per context pack
14CLI commands
426tests in the pytest suite

Architecture

How it works

One build pipeline feeds a dual-layer store; three read paths consume it. Session knowledge flows back in as first-class graph nodes.

Capabilities

Feature sets

Six capability groups. The amber-keyed group is the durable-memory layer — knowledge that persists and stays linked to code across agent sessions.

Core engine

Graph construction

  • Dual-layer store — SQLite for durable indexed lookup + FTS5 full-text search; NetworkX for traversal algorithms
  • 6 languages parsed with tree-sitter (Python, TS/JS, Go, Rust, Java, C/C++), regex fallback for the rest
  • Git-aware — commit history, per-file churn, incremental update and watch
  • Layer detection — files classified into presentation / business / data / infra / config / utility / test
  • Convention mining — naming styles, doc coverage, code idioms

Analysis

Queries & impact

  • Symbol lookup — exact, prefix, and full-text; callers and callees at any depth
  • Impact analysis — blast radius of changing a symbol: affected code, files, tests
  • Hot paths — most active code by PageRank × commit frequency
  • Symbol-level diff — added / removed / modified symbols between any two git refs
  • Test coverage mapping and TODO/FIXME extraction

Context packs

Session-start context

  • Token-budgeted CLAUDE.md — ~2–8k-token snapshot; tiered so essentials always fit
  • Role overlays — debug, review, feature re-rank content for the task at hand
  • Focus mode — pack centered on one file: its symbols, callers, imports, importers
  • Protects hand-written CLAUDE.md — never overwrites without --force
  • HTML reports for humans (codegraph report)

Durable memory

Knowledge that persists

  • Linked session notes — decisions and gotchas stored as graph nodes with provenance, edged to the symbols they describe
  • Smart surfacing — notes on hot-path code are preferred in packs and shown on symbol lookups
  • LLM enrichment — API-generated summaries for undocumented symbols; cached, staleness-tracked, survive updates
  • Graph lint — codegraph lint --fix detects and repairs graph rot
  • Maintenance recipes — codegraph hooks prints session-end hooks and cron lines

MCP server

Agent integration

  • 18 query tools — find symbol, callers, dependencies, impact, hot paths, health, notes, compress, more
  • 2 resources — graph://context-pack and graph://summary for instant orientation
  • Two transports — stdio per session, or SSE for one shared live graph
  • PR pattern mining — recurring review-feedback themes from merged GitHub PRs

VS Code

Editor experience

  • @codegraph chat participant for Copilot, plus 12 registered language-model tools
  • 3D graph view — force-directed, layers stratified on Z-planes
  • Error tracing — live diagnostics pulse error nodes red, fade unrelated code
  • Backend choice — full Python backend over MCP, or zero-install native WASM parsing in-process

Rollout

Deployment options

Four ways to run it, from a single laptop to a team-shared service. They compose — most teams land on per-dev CLI plus the automation loop.

Per-developer CLI

Best for: individual developers, default setup

Each editor session spawns the MCP server as a stdio subprocess against the local clone. No ports, no shared state, nothing to operate.

pip install -e ".[all-langs]"
codegraph init .        # build the graph
codegraph serve .       # stdio MCP server

Shared SSE server

Best for: one live graph across multiple clients

A single long-running server on port 8765 that Claude Code desktop and the VS Code extension connect to simultaneously — everyone queries the same up-to-date graph.

codegraph serve . --transport sse --port 8765
# VS Code: "codegraph.transport": "sse",
#          "codegraph.ssePort": 8765

VS Code native backend

Best for: zero-install rollout, no Python required

The extension's built-in Node/WASM backend parses all six languages in-process and answers the core read tools. Enrichment, diff, and PR mining stay CLI-only.

// settings.json
"codegraph.backend": "native"

Automation loop

Best for: keeping graphs fresh without anyone thinking about it

codegraph watch re-indexes on every git change; a session-end hook or nightly cron folds in commits and repairs rot. codegraph hooks prints the config.

# nightly cron
codegraph update . --re-enrich && \
codegraph lint . --fix

Prerequisites

Requirements & configuration

Everything lives in the repo — no external services required. LLM enrichment and PR mining are optional and key-gated.

Runtime
Python ≥ 3.11 for the backend; Node only for building the VS Code extension (or none at all with the native backend)
Install
pip install -e ".[all-langs]" · add ,git extra for GitHub PR mining
Artifacts
All graph data under .codegraph/ in the repo root (SQLite DB, snapshot, notes, caches) — add to backup/ignore policies once
Config
Environment variables or optional codegraph.toml; no config needed for core use
Optional keys
CODEGRAPH_ANTHROPIC_API_KEY (LLM summaries) · CODEGRAPH_GITHUB_TOKEN (PR mining)
Network
Fully offline for indexing and queries; outbound HTTPS only for the two optional key-gated features
